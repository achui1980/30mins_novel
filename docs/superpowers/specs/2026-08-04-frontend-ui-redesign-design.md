# 30分钟读懂一本书 — 前端 UI 重设计

状态：设计已通过分段确认，待生成实施计划。
日期：2026-08-04

## 1. 背景与目标

现有前端（`frontend/src/`：`HomePage.jsx` / `ProcessingPage.jsx` / `ReaderPage.jsx` +
纯 CSS `styles.css`）功能完整，但视觉呈现是通用 SaaS 风格：单一紫色主色调、扁平卡片、无
图标、排版和间距不统一，缺少与"读书"这个产品定位相配的品牌感。

用户对现状的具体不满（多选）：排版和间距混乱、整体风格太朴素/没有设计感、缺少品牌感/个性、
布局本身不合理。这是对全app的不满，不是某一页的局部问题。

本次目标：对 `HomePage` / `ProcessingPage` / `ReaderPage`（含其 6 个 tab）做**一次性全量
重设计**，建立一套"文学/阅读感"的视觉语言（区别于当前的通用 tech-SaaS 感），并引入
Tailwind CSS 作为新的样式实现方式。

### 范围与约束（已确认）

- **三页全部重做**，一次性完成，不分阶段上线。
- **只做浅色模式**，不需要暗黑模式。
- **不做响应式/窄屏适配**，只需支持正常桌面窗口宽度（不处理移动端/窄屏折叠）。
- **引入 Tailwind CSS** 替代现有纯 CSS 方案（需要改 `vite.config.js`、新增构建依赖、
  重写所有 JSX 的 className）。
- **引入 `lucide-react`** 图标库（线性图标，1.5px 描边）。
- 8 个固定关系分类（`RelationCategory`：家人/爱人/朋友/敌人/师徒/主仆/同盟/其他）及其
  `CATEGORY_COLORS` 映射保持不变，只是颜色值需要适配新的配色体系（见 4.4）。
- 后端逻辑、API、数据结构均不改动，纯前端视觉与布局重构。

## 2. 设计方向

目标风格：**文学/阅读感**——温暖基调、衬线点缀、让人联想到实体书，而非通用科技产品。

配色方向从 3 个候选（宣纸墨迹 / 墨蓝书卷 / 竹青手账）中选定**「宣纸墨迹」**：暖米白纸感
背景 + 墨黑正文 + 朱红/印章红点缀主色 + 松墨绿辅助色。相比蓝/紫类科技配色，更具"书卷/
印章"的东方文学气质，品牌记忆点更强。

字体方向：**正文无衬线 + 标题衬线混搭**——UI/表单/正文用无衬线，标题/强调文本（书名、
一句话简介等）用衬线，营造"书名页"的感觉。

## 3. 设计 Token

### 3.1 配色（Tailwind `theme.extend.colors`）

| Token | 色值 | 用途 |
|---|---|---|
| `paper-50` | `#FAF6EE` | 页面背景 |
| `paper-100` | `#F3ECDD` | 次级面板/hover 背景（如左右两栏背景） |
| `ink-900` | `#2B2724` | 主文本色 |
| `ink-600` | `#6B6259` | 次级/弱化文本色 |
| `ink-300` | `#D9D2C4` | 分割线、卡片边框（用发丝细边而非重阴影） |
| `seal-600` | `#B33A3A` | 品牌主色：主按钮、激活态、强调下划线（谨慎使用，不做大面积铺色） |
| `seal-700` | `#8F2C2C` | 主色 hover/pressed 态 |
| `seal-100` | `#F5DEDA` | 主色浅底（标签/徽章背景） |
| `pine-600` | `#3F5B4E` | 次级强调：成功/完成态 |
| `pine-100` | `#DCE6E1` | 次级浅底 |
| `amber-600` | `#C9A15B` | 三级强调：警告/提示态 |
| `danger-600` | `#C0392B` | 错误态（与 `seal-600` 刻意区分，避免品牌色与错误色混淆） |

### 3.2 字体

- 正文/UI：无衬线，`"Noto Sans SC", Inter, system-ui` —— 按钮、表单、正文、数据。
- 标题/强调：衬线，`"Noto Serif SC", Georgia` —— 页面标题（书名感）、区块小标题、
  一句话简介等，用于强化文学感。
- 字号阶梯：Display 32/40（衬线，书名级）、H1 24/32（衬线）、H2 18/28（无衬线半粗）、
  Body 15/24、Small 13/20（弱化色）。

### 3.3 间距/形状/阴影

- 圆角：卡片 12px，按钮/输入框 8px，标签/分段控件用胶囊形（full-round）。
- 阴影：极轻/克制——`shadow-sm: 0 1px 2px rgba(43,39,36,.04)`；只有悬浮/弹层元素用
  `0 8px 24px rgba(43,39,36,.08)`。
- 优先用 1px `ink-300` 发丝边框而非投影，营造"纸页边缘"感而非"悬浮卡片"感。

### 3.4 组件样式约定

- **按钮**：primary = `seal-600` 实底 + 白字；ghost = 透明 + ink 描边；danger =
  `danger-600` 描边，hover 时填色。
- **Tabs**：下划线风格（非胶囊）；激活 tab 用衬线字体 + `seal-600` 下划线（书籍章节
  标签的感觉）。
- **卡片**：`paper-50`/白底 + 1px `ink-300` 发丝边框；人物卡可用 4px 左侧色条，颜色取自
  现有 `CATEGORY_COLORS`（关系分类色，需要把色值适配进新配色体系，保持语义映射不变）。
- **徽章/状态标签**：胶囊形，浅底 + 对应深字（完成=松绿、失败=danger、处理中=amber）。
- **图标**：`lucide-react`，1.5px 描边，默认 `ink-600`，激活/强调时用 `seal-600`。

## 4. 页面布局

### 4.1 通用三栏应用壳

三个页面（`HomePage` / `ProcessingPage` / `ReaderPage`）共享同一个**持久化三栏布局壳**：

- **左栏**（约 130–150px，`paper-100` 背景）：常驻"书架"——顶部品牌/logo，下方是所有
  作品的竖直紧凑列表（`.shelf-item`，左侧色条：`pine-600` 常态 / `seal-600` 当前选中），
  底部有"＋ 新建"入口。这个列表同时充当**作品切换器**，在任意页面都可见。原先
  HomePage 里"过往作品"用大网格卡片展示的方案已被取代——过往作品统一收纳进左栏紧凑列表，
  HomePage 中间区域只保留上传相关内容（拖拽区、granularity 切换，可含空状态文案）。
- **中栏**（弹性宽度，最大区域）：每页的主内容——HomePage 是上传拖拽区；ProcessingPage
  是进度条 + phase-chip 步骤条；ReaderPage 是 tab 栏（总览·人物·情节线·时间轴·图谱·
  问答）+ 当前 tab 的主体内容。
- **右栏**（约 190–210px，`paper-100` 背景）：随页面/tab 变化的上下文详情面板，具体内容
  见 4.2 表格。不需要响应式收起逻辑（不支持窄屏）。

### 4.2 各页面/Tab 的右栏内容（已逐一确认）

| 页面/Tab | 右栏内容 |
|---|---|
| 首页（Home） | 统计概览（作品总数/本周新增/失败数） |
| 处理页（Processing） | 阶段说明文字/预计耗时/简单日志 |
| 总览（Overview） | 常驻"你可能想问"推荐问题列表 + 快捷提问输入框 |
| 人物（Characters） | 选中人物的详情（姓名/角色/引言、人物关系列表、出场章节） |
| 情节线（Arcs） | 特例：全书章节目录导航（`.toc-row`，随阅读位置高亮/可点击跳转），**不是**"选中详情"模式 |
| 时间轴（Timeline） | 选中事件的详情 |
| 图谱（Graph） | 选中节点/边的详情 + 原文证据引用（复用现有 `graph-detail`/`evidence` 组件逻辑） |
| 问答（Ask） | 常驻"你可能想问"推荐问题列表（与总览一致） |
| 设置（Settings） | 无右栏内容 |

设计原则：右栏默认是"选中项详情"（人物/时间轴/图谱三个 tab 遵循此模式），但总览/问答两个
tab 特例为"常驻推荐提问入口"，情节线 tab 特例为"全书导航"——三类特例都是基于实际内容需求
确认过的，非默认规则的疏漏。

未选中任何项时，右栏显示占位提示文案（如"点击左侧人物卡查看详情"），不展示假数据。

## 5. 技术方案

- 新增 Tailwind CSS 依赖（`tailwindcss` + 配套 `postcss`/`autoprefixer`），修改
  `frontend/vite.config.js` 接入 Tailwind 构建流程，新增 `tailwind.config.js` 写入
  4.1/4.3 节的 token（colors/fontFamily/borderRadius/boxShadow extend）。
- 新增 `lucide-react` 依赖，在按钮/Tab/卡片/徽章等位置按 3.4 节约定引入图标（具体使用哪个
  图标对应哪个位置留给实施阶段决定，不在本设计文档中逐一枚举）。
- 逐步将 `HomePage.jsx` / `ProcessingPage.jsx` / `ReaderPage.jsx`（含其内部子组件
  `Overview`/`AskFeature`/`StoryFeature`/`Arcs`/`TimelineTab`/`GraphTab`/`Settings`）
  的 className 从现有 `styles.css` 迁移到 Tailwind utility class；三栏应用壳作为一个
  新的共享布局组件抽出（例如 `frontend/src/components/AppShell.jsx`），三个页面都包裹
  在其中，避免重复实现左栏作品列表逻辑。
- 现有 `constants.js` 中的 `CATEGORY_COLORS`/`PHASE_LABELS` 等常量保留结构，只更新色值
  以对齐新 token（语义映射——哪个分类/阶段对应哪种强调色——保持不变）。
- `styles.css` 中不再需要的规则在迁移完成后删除；如有 Tailwind 无法优雅表达的极少数样式
  （例如复杂的胶囊分段控件细节），可保留少量自定义 CSS 类，但应是例外而非常态。
